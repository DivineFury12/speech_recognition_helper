Голосовой ассистент для задач и встреч

Это экспериментальная ветка experimental/gigachat-backend. В ней собран рабочий прототип: речь распознаёт GigaAM, команды разбирает GigaChat, данные хранятся в SQLite, интерфейс написан на Vue. Прежде чем переносить это в main, ветку стоит посмотреть всей командой.

Ассистенту можно сказать или написать что-нибудь обычными словами: «Напомни завтра в 10 позвонить Ивану», «Что у меня на неделе?», «А перенеси её на пятницу». Он поймёт, что нужно, переспросит, если чего-то не хватает, сделает и ответит текстом, а если включить озвучку, то и голосом.


Как запустить

Проще всего на Windows одной командой из корня проекта:

    .\run.ps1

При первом запуске скрипт сам создаст виртуальное окружение для бэкенда, поставит зависимости, сделает файл backend\.env из шаблона, откроет бэкенд и фронтенд в двух окнах и откроет браузер на http://127.0.0.1:5173.

Если запустить .\run.ps1 -Prod, фронтенд соберётся, и всё будет работать на одном адресе http://127.0.0.1:8000. Этот вариант подходит для выкладки на сервер. Флаг -NoBrowser не открывает браузер.

Флаг -NoVoice запускает ассистента без голоса: только текст, без распознавания речи и озвучки. В интерфейсе пропадают кнопка микрофона и выбор голоса. В этом режиме не нужны ни видеокарта, ни torch, ни модели, хватает Python, Node и ключа GigaChat. То же самое включается переменной VOICE_ENABLED=false в backend\.env. На Linux и macOS то же самое делает ./run.sh (и ./run.sh --prod).

Можно запускать и по-старому, в двух окнах терминала. В первом бэкенд:

    cd backend
    .\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000

Во втором фронтенд:

    cd frontend
    npm run dev

Без ключа GigaChat ассистент тоже работает, но понимает команды по простым правилам и хуже справляется со свободными формулировками. Как получить ключ, написано ниже.


Запуск в Docker

Этот способ нужен, чтобы передать проект или выложить его на сервер: всё уже внутри образа — сервер, собранный интерфейс, сертификаты, голоса и модели. Нужен только Docker и ключ GigaChat в backend\.env. После запуска всё открывается на одном адресе http://127.0.0.1:8000.

Есть три варианта, все собираются из одного Dockerfile в корне проекта:

- без голоса, только текст. Образ около 270 МБ, хватает любого компьютера:

    docker compose -f docker-compose.lite.yml up -d --build

- с голосом на видеокарте NVIDIA. Нужна видеокарта, около 15 ГБ свободного места и 8 ГБ памяти для Docker:

    docker compose up -d --build

- с голосом на процессоре. Работает без видеокарты, но озвучка и распознавание заметно медленнее:

    docker compose -f docker-compose.cpu.yml up -d --build

Записи хранятся в томе assistant-data и не пропадают при пересборке. Остановить: та же команда с down вместо up -d --build. Для выкладки наружу задайте в backend\.env ACCESS_CODE и поставьте сервер за HTTPS с COOKIE_SECURE=true.

Что проверено: вариант без голоса собран и запущен через docker compose, страница открывается, GigaChat из контейнера отвечает, сценарии с уточнением и сдвигом проходят. Варианты с голосом проверены на синтаксис, но целиком не собирались: на машине разработки не хватило места на диске и памяти для Docker.

В папке backend остались старые Dockerfile и docker-compose: они собирают только API без интерфейса и сохранены для совместимости.


Как получить ключ GigaChat

1. Зайдите на https://developers.sber.ru/studio через Сбер ID.
2. Создайте проект GigaChat API. Физлицам доступен бесплатный тариф Freemium.
3. В настройках проекта нажмите «Получить ключ» и скопируйте Authorization key. Это одна длинная строка, не Client ID и не Client Secret по отдельности.
4. Откройте backend\.env и впишите:

    GIGACHAT_CREDENTIALS=ваш_ключ
    GIGACHAT_SCOPE=GIGACHAT_API_PERS

   Для юрлиц scope будет GIGACHAT_API_B2B или GIGACHAT_API_CORP. Переменную можно назвать и GIGAKEY, это тоже сработает.
5. Перезапустите бэкенд. Если всё в порядке, в его окне при старте будет строка «LLM provider: gigachat», а на каждую команду появится запрос к api.giga.chat с ответом 200 OK.

Что полезно знать:

- Модель называется GigaChat-2. Для новых ключей просто GigaChat не подходит, сервер отвечает «No such model».
- Бесплатно физлицам на год дают 250 млн токенов на модель Lite. Одна команда ассистента тратит примерно 1–2 тысячи токенов, так что для прототипа хватает с большим запасом.
- Эмбеддинги в бесплатный пакет не входят, поэтому поиск по смыслу сделан через обычную чат-модель (подробнее в разделе про решения).
- С 1 сентября 2026 года новые клиенты оплачивают модели через cloud.ru. Если кабинет просит оплату, это оттуда.
- GigaChat использует сертификат НУЦ Минцифры. Нужные сертификаты уже лежат в backend/certs и подключаются сами. Промежуточный сертификат действует до марта 2027 года, потом его надо будет скачать заново с https://www.gosuslugi.ru/crt.
- Ключ секретный. Он хранится только в backend\.env, а этот файл в git не попадает. Если ключ куда-то утёк, перевыпустите его в кабинете.


Что умеет ассистент

Всё, что требует задание:

- создать задачу или напоминание: «Напомни мне завтра в 10 утра позвонить Ивану», «В пятницу нужно отправить отчёт», «Поставь задачу купить билеты до конца недели»;
- создать встречу: «Добавь встречу с командой завтра в 15:00», «В четверг в 11 у меня встреча с дизайнером»;
- показать записи за период, в том числе только определённого типа: «Что у меня сегодня?», «Какие задачи на завтра?», «Есть ли у меня встречи сегодня?», «Что запланировано на следующей неделе?»;
- найти старую запись: «Найди задачу про презентацию», «Когда у меня была встреча с Иваном?», «Я когда-то ставил задачу по договору, найди её»;
- понимать относительные даты: сегодня, завтра, послезавтра, в пятницу, через два часа, на следующей неделе, до конца недели или месяца, пятого числа;
- переспросить, если данных не хватает: на «Поставь встречу с Иваном завтра» он спросит время;
- принимать команды голосом (кнопка микрофона, до 25 секунд) и отвечать голосом: в шапке выбирается голос — Никита, Сергей, Алина или голос браузера;
- хранить всё между запросами в базе backend/data/assistant.db.

И дополнительные возможности из задания:

- менять записи голосом: «Перенеси встречу с дизайнером на 17:00», «Перенеси планёрку на 11», «Сдвинь её на час позже», «Перенеси отчёт на 3 дня», «Сделай её на полчаса», «Переименуй её в …»;
- удалять: «Удали напоминание про таблетки», и перед удалением ассистент переспросит;
- отмечать выполненными: «Отметь задачу про отчёт выполненной», «Готово» или просто сообщить «Я купил молоко» — ассистент найдёт задачу «Купить молоко». В списке для этого есть галочка. У повторяющейся записи отмечается только текущий раз, а запись переходит на следующую дату;
- помнить, о чём шла речь: «А перенеси её на завтра» относится к последней записи. Если подходящих записей несколько, он спросит, какую именно, и можно ответить «вторую»;
- уточнять действия: на «Перенеси встречу» он спросит, на когда, а на «Отметь выполненной» без контекста — какую запись. Ответ «нет» или «не надо» отменяет уточнение;
- предупреждать о пересечении встреч, в том числе с повторяющимися и при переносе, и предлагать либо поставить всё равно, либо назвать другое время;
- повторяющиеся записи: «Планёрка каждый понедельник в 10», «по будням», «каждый день», «каждый месяц»;
- искать по смыслу: на «Найди соглашение с исполнителем» найдётся «Подготовить договор с подрядчиком». Работает на локальной модели эмбеддингов E5 (или FRIDA);
- не создавать дубли: если повторить ту же команду, ассистент вернёт уже существующую запись;
- календарь: кнопка с календарём в шапке скачивает файл assistant.ics. Его можно открыть в Outlook или Apple Calendar либо импортировать в Google Calendar. Когда прототип будет выложен на сервер, на тот же календарь можно будет подписаться по ссылке;
- несколько пользователей: у каждого браузера свои записи.

Если навести мышку на значок «?» рядом с заголовком, появится список всего, что умеет ассистент. Справа на странице записи на сегодня, на неделю и без срока, каждую можно отметить, изменить или удалить.


Пользователи и защита

Логина и пароля нет, для прототипа это лишнее. Вместо этого:

- Каждый браузер считается отдельным пользователем. При первом заходе сервер выдаёт подписанную куку со случайным номером пользователя. Прочитать её из JavaScript нельзя, подделать чужую без секретного ключа сервера тоже нельзя. Каждый видит только свои записи.
- Если стенд открыт наружу, задайте в backend\.env переменную ACCESS_CODE. Тогда без этого кода приложение не пустит дальше экрана входа, и посторонние не потратят лимиты GigaChat. Подобрать код перебором не выйдет: не больше 10 попыток за 10 минут.
- Запросы, которые что-то меняют, должны приходить с особым заголовком, поэтому чужой сайт не сможет действовать от имени пользователя.
- К ассистенту можно обратиться не больше 30 раз в минуту с одного браузера. Число меняется через RATE_LIMIT_PER_MINUTE.
- Ссылка на календарь личная. Кто её знает, тот увидит записи, поэтому лучше её не публиковать.

Чего пока нет: если очистить куки, записи останутся в базе, но браузер их больше не увидит. Перенести профиль на другое устройство тоже нельзя. Для этого нужен настоящий вход, например через Сбер ID.


Голос

Речь распознаётся локально моделью GigaAM-v3, на видеокарте или на процессоре.

Чтобы голос заработал на Windows с видеокартой NVIDIA, нужно один раз поставить ffmpeg, torch с поддержкой CUDA и GigaAM:

    winget install Gyan.FFmpeg
    cd backend
    .venv\Scripts\activate
    pip install torch==2.10.0 torchaudio==2.10.0 --index-url https://download.pytorch.org/whl/cu126
    "torch==2.10.0+cu126`ntorchaudio==2.10.0+cu126" | Out-File -Encoding ascii constraints.txt
    pip install -c constraints.txt --extra-index-url https://download.pytorch.org/whl/cu126 "gigaam[longform] @ git+https://github.com/salute-developers/GigaAM.git"
    del constraints.txt

Файл constraints.txt нужен, чтобы при установке GigaAM pip не заменил torch с CUDA на обычную версию без поддержки видеокарты. Если видеокарты нет, ставьте torch с адреса https://download.pytorch.org/whl/cpu.

При первом запуске сервер скачает модель, около 430 МБ. На RTX 2060 фраза распознаётся примерно за секунду. Если GigaAM не установлена, сервер всё равно запустится: текстом пользоваться можно, а голосовые запросы будут отвечать ошибкой.

Docker-вариант описан ниже, в разделе «Запуск в Docker».


Голоса озвучки

Ответы ассистента озвучиваются локальной моделью XTTS-v2 тремя голосами:

- Никита и Сергей — клоны по их записям. Образцы лежат в backend/voices (nikita.wav, sergey.wav), они уже очищены от шума и тишины и выровнены по громкости;
- Алина — встроенный женский голос модели.

В шапке страницы есть кнопка с динамиком: в выпадающем списке выбирается голос, рядом с каждым есть кнопка, чтобы послушать его. Там же можно выбрать голос браузера или выключить озвучку. Выбор запоминается.

Перед озвучкой даты, время и числа переводятся в слова, чтобы модель читала их правильно: «15:00» звучит как «пятнадцать ноль-ноль», «на 21 октября» — как «на двадцать первое октября», «2 записи» — как «две записи».

Модель весит около 1,9 ГБ. Её скачивает run.ps1 при первом запуске или команда python -m assistant.models_download в папке backend. В Docker-образ она попадает при сборке. После старта сервера модель загружается в фоне примерно минуту; пока она грузится, ответы читает голос браузера. На RTX 2060 фраза длиной пять секунд синтезируется примерно за пять секунд, повторные фразы берутся из памяти мгновенно.

Как добавить свой голос: записать 30–60 секунд обычной речи в тихой комнате, положить файл в backend/voices и добавить строку в список VOICES в backend/assistant/tts.py.

Важно: голоса клонируются только с согласия их владельцев. Записи голосов лежат в приватном репозитории, публиковать их не стоит. Лицензия XTTS-v2 некоммерческая: для прототипа и демонстрации это нормально, для коммерческого продукта модель нужно будет заменить.


Как сменить модель

Модель выбирается переменной LLM_PROVIDER в backend\.env:

- gigachat — GigaChat, нужен ключ;
- local — локальная модель Qwen из backend/ml.py, сначала нужно выполнить pip install -r requirements-local.txt;
- rules — без модели, только правила;
- если ничего не указать, ассистент возьмёт GigaChat при наличии ключа, а иначе правила.

Если модель не ответила или ответила что-то непонятное, команду разберут правила, и ассистент продолжит работать.


Как это устроено

Браузер отправляет текст или запись голоса на сервер на FastAPI. Голос сначала проходит через ffmpeg и GigaAM и превращается в текст, дальше текст и голос обрабатываются одинаково. Модель определяет, чего хочет пользователь, и возвращает это в виде структуры: что сделать, какой тип записи, название, дата и время словами. Даты и время по часовому поясу пользователя считает обычный код, не модель. Затем бизнес-логика создаёт, ищет, меняет или удаляет записи в SQLite, задаёт уточняющие вопросы и собирает ответ.

Где что лежит:

- backend/app.py — запуск сервера и распознавание речи;
- backend/assistant/llm — подключение GigaChat и локальной модели;
- backend/assistant/nlu.py и dates.py — разбор команд и дат;
- backend/assistant/service.py — логика ассистента: действия, уточнения, контекст, конфликты встреч;
- backend/assistant/search.py — поиск: по словам, потом по смыслу;
- backend/assistant/embeddings.py — локальные эмбеддинги E5 и FRIDA;
- backend/assistant/tts.py и speech_text.py — озвучка голосами и подготовка текста для неё;
- backend/assistant/storage.py — база данных;
- backend/assistant/auth.py — куки, код доступа, лимиты;
- backend/assistant/api.py — HTTP-ручки по контракту openapi.yaml;
- frontend/src — интерфейс на Vue 3, TypeScript и Pinia; типы генерируются из openapi.yaml командой npm run gen:api.


Почему сделано именно так

Речь распознаём локально, а команды понимает внешняя модель. GigaAM хорошо знает русский и уже была в проекте. Маленькая локальная Qwen плохо понимает фразы вроде «завтра в 3 дня» и путается в уточнениях, а GigaChat для прототипа бесплатна и с русским справляется хорошо.

Даты считает код. Модель только находит в запросе слова вроде «до конца недели», а в конкретную дату их переводит программа. Так результат предсказуем и его можно проверить тестами.

Правила остаются как запасной вариант. Даже если GigaChat недоступна, основные сценарии работают, просто формулировки нужно выбирать проще.

Поиск по смыслу работает на локальных эмбеддингах. Сначала ищем по словам с учётом окончаний. Если точного совпадения нет, сравниваем смысл запроса с названиями записей с помощью модели E5: она маленькая (около 470 МБ) и быстро работает на процессоре. Векторы записей считаются один раз и хранятся в той же базе SQLite. По желанию можно включить FRIDA (EMBEDDING_MODEL=frida): она точнее, но весит около трёх гигабайт и на процессоре заметно медленнее. Если модели эмбеддингов нет, по смыслу ищет GigaChat. Эмбеддинги самого GigaChat в бесплатный пакет не входят.

Ответ ассистента собирается кодом, а не пишется моделью, поэтому он всегда совпадает с тем, что действительно сохранено.

Удаление голосом требует подтверждения, остальные действия выполняются сразу.

База данных — SQLite: один файл и никакого отдельного сервера. Если схема поменялась, база обновляется сама при запуске.

Календарь подключается подпиской по ссылке, а не через API Google. Так он работает с любым календарём и не требует отдельной авторизации.

Озвучка локальная, на XTTS-v2: она умеет повторять голос по короткой записи и говорит по-русски. Облачные сервисы не подошли: у SaluteSpeech нельзя сделать свой голос, а остальные платные и отправляют данные за границу.

Что взято из ветки main (работа Сергея Елисеева): модели эмбеддингов E5 и FRIDA с переключением через EMBEDDING_MODEL, защита от повторного создания одинаковой записи и хранение чата в браузере между перезагрузками. Хранение в PostgreSQL с pgvector пока не перенесено: для запуска без дополнительной установки оставлен SQLite.


Настройки в backend\.env

- GIGACHAT_CREDENTIALS — ключ GigaChat (можно назвать GIGAKEY);
- GIGACHAT_SCOPE — по умолчанию GIGACHAT_API_PERS;
- GIGACHAT_MODEL — по умолчанию GigaChat-2;
- LLM_PROVIDER — gigachat, local или rules;
- ACCESS_CODE — код доступа к стенду; если пусто, кода нет;
- SESSION_SECRET — секрет для подписи кук; если не задан, создаётся сам в backend/data;
- COOKIE_SECURE — true, если сайт работает по HTTPS;
- RATE_LIMIT_PER_MINUTE — сколько запросов в минуту можно одному пользователю, 0 означает без ограничений;
- VOICE_ENABLED — false, чтобы работать вообще без голоса (только текст);
- ASR_ENABLED — false, если не нужно загружать модель распознавания речи;
- EMBEDDING_MODEL — e5 (по умолчанию), frida или none;
- TTS_ENABLED — false, если не нужна озвучка голосами;
- TTS_DEVICE — auto, cuda или cpu;
- DB_PATH — где лежит база, по умолчанию data/assistant.db;
- CORS_ORIGINS — адрес фронтенда, если он открывается с другого домена.

Во фронтенде, в файле frontend\.env.local, есть VITE_USE_MOCKS=true, чтобы работать на заглушках без бэкенда, и VITE_API_URL, если API находится на другом адресе.
