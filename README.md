# Голосовой ассистент для задач и встреч

> **Ветка `experimental/gigachat-backend` — тестовая и экспериментальная.**
> Здесь собран рабочий прототип: распознавание речи GigaAM, разбор команд через
> GigaChat, хранение в SQLite и веб-интерфейс на Vue. Перед переносом в `main`
> ветку нужно проверить командой. Модель меняется одной переменной окружения:
> GigaChat ↔ локальная Qwen ↔ правила без модели.

Пользователь говорит или пишет в свободной форме: «Напомни завтра в 10 позвонить
Ивану», «Что у меня на неделе?», «А перенеси её на пятницу». Ассистент понимает
запрос, переспрашивает, если не хватает данных, выполняет действие и отвечает
текстом и, по желанию, голосом.

## Быстрый старт (Windows)

```powershell
.\run.ps1
```

Скрипт при первом запуске сам создаст `backend\.venv`, поставит зависимости,
создаст `backend\.env` из шаблона, откроет бэкенд и фронтенд в двух окнах и
откроет браузер на http://127.0.0.1:5173. Впишите ключ GigaChat в `backend\.env`
(см. «Как получить ключ GigaChat») и перезапустите — без ключа ассистент работает
на правилах.

- `.\run.ps1 -Prod` — собрать фронтенд и запустить всё на одном порту: http://127.0.0.1:8000.
- `.\run.ps1 -NoBrowser` — не открывать браузер.
- Linux/macOS: `./run.sh` и `./run.sh --prod`.

Ручной запуск, как раньше, тоже работает — два окна:

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

```powershell
cd frontend
npm run dev
```

## Как получить ключ GigaChat

1. Зайдите на [developers.sber.ru/studio](https://developers.sber.ru/studio) через Сбер ID.
2. Создайте проект **GigaChat API** (для физлица — тариф Freemium, бесплатно).
3. В настройках проекта нажмите «Получить ключ» и скопируйте **Authorization key** — длинную строку в base64.
   Это не Client ID и не Client Secret по отдельности.
4. Впишите его в `backend\.env`:

   ```
   GIGACHAT_CREDENTIALS=ваш_ключ
   GIGACHAT_SCOPE=GIGACHAT_API_PERS
   ```

   Для юрлиц scope — `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`. Имя `GIGAKEY`
   тоже понимается.
5. Запустите бэкенд. В логе должно быть `LLM provider: gigachat`, а на каждую
   команду — строка `POST https://api.giga.chat/v1/chat/completions "200 OK"`.

Что важно знать:

- **Модель** — `GigaChat-2` (Lite). Имя `GigaChat` API нового ключа не принимает (`404 No such model`).
  Список доступных моделей ключа — `GET /v1/models` в API GigaChat.
- **Бесплатно** для физлиц на 12 месяцев: 250 млн токенов Lite, 40 млн Pro, 25 млн Max.
  Одна команда ассистента — около 1–2 тыс. токенов.
- **Эмбеддинги в бесплатный пакет не входят** (`402 Payment Required`) — поэтому поиск
  по смыслу сделан через чат-модель, см. «Решения».
- С 1 сентября 2026 новые клиенты оплачивают модели через [cloud.ru](https://cloud.ru); если кабинет
  просит оплату — это оттуда.
- **Сертификат.** GigaChat использует сертификат НУЦ Минцифры. Корневой и промежуточный
  сертификаты уже лежат в `backend/certs/russian_trusted_ca.pem` и подключаются сами.
  Промежуточный действует до марта 2027, обновить — с [gosuslugi.ru/crt](https://www.gosuslugi.ru/crt).
- **Ключ — секрет.** Он живёт только в `backend\.env` (в `.gitignore`) или в переменных
  окружения сервера, во фронтенд и в git не попадает. Если ключ куда-то утёк — перевыпустите его в кабинете.

## Пользователи и защита

Логина и пароля нет — это прототип, а не сервис с учётными записями.

- **Пользователь = браузер.** При первом запросе сервер выдаёт куку `sa_session`
  со случайным ID пользователя, подписанную HMAC-SHA256. Кука `HttpOnly`
  (недоступна JavaScript), `SameSite=Lax`, `Secure` при HTTPS. Подделать чужой ID
  без секрета сервера нельзя. Все записи, диалоги и календарь — только свои.
- **Код доступа для стенда.** Если задать `ACCESS_CODE`, пока его не ввели, всё API,
  кроме `/health`, отвечает 401, а интерфейс показывает экран ввода кода. Это
  защищает лимиты GigaChat от посторонних. Попыток ввода — не больше 10 за 10 минут с одного IP.
- **CSRF.** Изменяющие запросы с кукой должны содержать заголовок
  `X-Requested-With: assistant` — чужой сайт не может его отправить без разрешения CORS.
- **Лимит запросов** к ассистенту — `RATE_LIMIT_PER_MINUTE` (по умолчанию 30 в минуту на пользователя).
- **Календарь** открывается по персональной ссылке с подписанным токеном — календарные
  приложения не умеют куки. Кто знает ссылку, видит записи; не публикуйте её.
- Ограничения размера: аудио до 10 МБ, текст команды до 2000 символов, период списка до года.
- Секрет подписи кук — `SESSION_SECRET` или автоматически созданный `backend/data/session_secret`.
  Если его удалить, все пользователи получат новые пустые профили.

Чего нет: восстановления доступа (очистил куки — потерял записи) и переноса между
устройствами. Для настоящего многопользовательского режима нужен вход (OAuth / Сбер ID / почта).

## Голос

Распознавание — **GigaAM-v3** локально, на видеокарте или CPU. Ответ голосом —
синтез речи браузера (Web Speech API), включается переключателем «Озвучка».

### Установка распознавания на Windows с NVIDIA

Проверено на RTX 2060 6 ГБ: GigaAM на `cuda:0`, фраза распознаётся примерно за 1 с.

```powershell
winget install Gyan.FFmpeg
cd backend
.venv\Scripts\activate
pip install torch==2.10.0 torchaudio==2.10.0 --index-url https://download.pytorch.org/whl/cu126
"torch==2.10.0+cu126`ntorchaudio==2.10.0+cu126" | Out-File -Encoding ascii constraints.txt
pip install -c constraints.txt --extra-index-url https://download.pytorch.org/whl/cu126 "gigaam[longform] @ git+https://github.com/salute-developers/GigaAM.git"
del constraints.txt
```

`constraints.txt` не даёт установке GigaAM заменить CUDA-сборку torch на CPU-версию.
Без видеокарты ставьте torch с `--index-url https://download.pytorch.org/whl/cpu`.
При первом старте скачаются веса GigaAM (~430 МБ) в `backend/.cache/gigaam`.
ffmpeg сервер находит сам, даже если терминал открыт до его установки.

Без GigaAM сервер всё равно стартует: текст работает, голосовые запросы отвечают 503.

### Docker (с распознаванием речи)

```powershell
cd backend
docker compose -f docker-compose.cpu.yml up --build   # или docker compose up --build для GPU
```

Ключ Compose берёт из `backend/.env` (нужен Docker Compose 2.24+). Записи — в томе
`assistant-data`, веса моделей — в `model-cache`. Docker-образы в этой ветке не собирались.

## Смена модели

| `LLM_PROVIDER` | Что используется |
| --- | --- |
| `gigachat` | GigaChat API, нужен ключ |
| `local` | Локальная Qwen из `backend/ml.py` (`pip install -r requirements-local.txt`) |
| `rules` | Только правила, без модели |
| не задано | `gigachat`, если есть ключ, иначе `rules` |

Все провайдеры реализуют один метод `complete(system, user) -> str`
(`backend/assistant/llm/`). Новая модель — это новый файл с классом и строка в
`create_provider`. Если модель недоступна, вернула ошибку или не-JSON, запрос
разбирают правила, и ассистент продолжает работать.

## Архитектура

```
Браузер (Vue 3)                         FastAPI (backend/app.py)
 ├─ чат, микрофон (MediaRecorder) ──►  SessionMiddleware: кука, CSRF, код доступа
 ├─ список записей, правка             │
 ├─ озвучка (Web Speech API)           ├─ /v1/assistant/audio ─► ffmpeg ─► GigaAM (ASR)
 └─ подсказка «?», календарь           │                                      │ текст
                                       ├─ /v1/assistant/messages ─────────────┤
                                       │                                      ▼
                                       │        Assistant (service.py) — бизнес-логика
                                       │          ├─ nlu.py: LLM → JSON, правила как запасной путь
                                       │          ├─ dates.py: даты, время, повторы — кодом
                                       │          ├─ search.py: по словам + по смыслу через LLM
                                       │          └─ уточнения, подтверждения, контекст, конфликты
                                       │                                      │
                                       ├─ /v1/entries, /v1/calendar ──► Storage (SQLite)
                                       └─ / ─► собранный фронтенд (режим одного сервера)
```

| Слой | Где | За что отвечает |
| --- | --- | --- |
| Голос | `backend/app.py` | приём аудио, ffmpeg, GigaAM |
| LLM | `backend/assistant/llm/` | провайдеры GigaChat / локальная / нет |
| Понимание | `backend/assistant/nlu.py`, `dates.py` | намерение, поля записи, даты |
| Бизнес-логика | `backend/assistant/service.py` | действия, диалог, контекст, конфликты |
| Поиск | `backend/assistant/search.py` | по словам и по смыслу |
| Данные | `backend/assistant/storage.py` | SQLite, миграции, повторы |
| Доступ | `backend/assistant/auth.py` | куки, код доступа, CSRF, лимиты |
| HTTP | `backend/assistant/api.py` | ручки по `openapi.yaml` |
| Интерфейс | `frontend/src` | Vue 3 + TypeScript + Pinia, типы из `openapi.yaml` |

Контракт — `openapi.yaml`. Фронтенд генерирует из него типы (`npm run gen:api`).

## Решения, принятые самостоятельно

- **Речь распознаётся локально (GigaAM), команды понимает внешняя модель (GigaChat).**
  GigaAM — одна из лучших моделей для русской речи и уже была в проекте. Маленькая
  локальная Qwen 0.8B плохо разбирает «завтра в 3 дня» и уточнения, а GigaChat
  бесплатен для прототипа и хорошо знает русский.
- **Даты считает код, а не модель.** Модель возвращает фразу («до конца недели»),
  код переводит её в дату по часовому поясу пользователя. ISO-дата от модели
  используется, только если модель назвала фразу, а код её не понял. Так ответы
  предсказуемы и тестируемы.
- **Правила как страховка.** Если GigaChat недоступен, все основные сценарии
  работают на регулярных выражениях — хуже с формулировками, но без отказов.
- **Поиск по смыслу через чат-модель.** Эмбеддинги GigaChat платные, а локальная
  FRIDA весит ~3 ГБ. Поэтому сначала ищем по словам (с основами слов), а если
  уверенного совпадения нет — отдаём список записей пользователя (до 150) модели
  и просим выбрать подходящие по смыслу. Для личного списка дел этого хватает.
- **Ответ ассистента собирается шаблоном в коде**, а не пишется моделью — он всегда
  совпадает с тем, что реально сохранено.
- **Удаление голосом — с подтверждением**, остальные действия — сразу.
- **Пользователь без регистрации** — подписанная кука. Для прототипа это убирает
  трение входа, а для стенда есть общий код доступа.
- **SQLite** — один файл, без отдельного сервера; миграции схемы выполняются при старте.
- **Календарь через iCalendar-подписку**, а не через Google API: работает с любым
  календарём и не требует OAuth.
- **Озвучка в браузере.** Серверный TTS потребовал бы ещё один ключ (SaluteSpeech);
  `/v1/speech/synthesize` пока отвечает 501.

## Переменные окружения (`backend/.env`)

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `GIGACHAT_CREDENTIALS` | — | ключ авторизации GigaChat (можно `GIGAKEY`) |
| `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` | scope ключа |
| `GIGACHAT_MODEL` | `GigaChat-2` | модель |
| `GIGACHAT_CA_BUNDLE` | `certs/russian_trusted_ca.pem` | сертификаты НУЦ Минцифры |
| `LLM_PROVIDER` | авто | `gigachat`, `local`, `rules` |
| `ACCESS_CODE` | — | код доступа к стенду; пусто — без кода |
| `SESSION_SECRET` | файл `data/session_secret` | секрет подписи кук |
| `COOKIE_SECURE` | `false` | `true` — кука только по HTTPS |
| `RATE_LIMIT_PER_MINUTE` | `30` | запросов к ассистенту в минуту на пользователя, `0` — без лимита |
| `ASR_ENABLED` | `true` | `false` — не загружать GigaAM |
| `DB_PATH` | `data/assistant.db` | файл базы |
| `CORS_ORIGINS` | — | origin фронтенда, если он на другом домене |
| `FRONTEND_DIST` | `../frontend/dist` | откуда раздавать собранный фронтенд |

Фронтенд (`frontend/.env.local`): `VITE_USE_MOCKS=true` — работать на моках без
бэкенда; `VITE_API_URL` — адрес API, если он не на том же домене (по умолчанию
запросы идут через прокси Vite).

## Тесты

```powershell
cd backend
.\.venv\Scripts\python.exe -m pytest
```

96 тестов: даты и повторы, все сценарии из задания и дополнительные (контекст,
конфликты, выбор, удаление с подтверждением), разделение пользователей, CSRF, код
доступа, календарь, миграция старой базы. Модель в тестах — заглушка, ключ не нужен.

Вживую с GigaChat проверены все фразы-примеры из задания и новые сценарии
(перенос «её», конфликт, повторы, поиск по смыслу, удаление). Голос проверен
синтезированной речью на RTX 2060; с живым микрофоном — вручную в браузере.

## Что не сделано и что улучшил бы

- **Ссылка на работающий прототип** — нужен хостинг. Готово к выкладке: `.\run.ps1 -Prod`
  или `uvicorn` + собранный фронт за HTTPS-прокси, с `ACCESS_CODE` и `COOKIE_SECURE=true`.
- **Вход и синхронизация между устройствами** — сейчас профиль живёт в куке браузера.
- **Эмбеддинги** (платный пакет GigaChat или локальная модель) — быстрее и дешевле
  поиска через чат-модель на больших списках.
- **Серверная озвучка** (SaluteSpeech) — одинаковый голос во всех браузерах.
- **Уведомления о напоминаниях** — сейчас напоминание видно в календаре и списке, но браузер не «звонит».
- **Исключения в повторах** («перенеси только эту планёрку») и окончание серии.
- **Docker-образы** собрать и проверить, добавить CI с тестами.
